smallest runner that can return your agent's final answer.

## The entry file created by `init`

New projects normally begin with the adapter generated by `agentopt init`:

- Python creates `agentopt_entry.py` and configures
  `run.python: "agentopt_entry:run"`.
- Node creates `agentopt.entry.mjs`, or `agentopt.entry.mts` in a TypeScript
  project, and configures `run.node` to its `run` export.

Keep the adapter small. Import the production agent, build any safe evaluation
fixture it needs, and return the final answer:

```python
# agentopt_entry.py
from agentopt import expose
from support.agent import reply

@expose
def run(input_text: str | None):
    return reply(input_text or "", tenant="evaluation")
```

```ts
// agentopt.entry.mts
import { expose } from "agentopt";
import { reply } from "./src/support/agent.js";

export const run = expose(async (input: string | null) => {
  return reply(input ?? "", { tenant: "evaluation" });
});
```

The direct module targets below are equivalent alternatives; the generated
filename is a convention, not a runtime requirement.

run:

SYSTEM = "You are a concise support agent."

## Multiple agents with named surfaces

Suppose the production path calls a router and then a responder. Test the
router's label directly instead of trying to infer it from the final response.

```python
# Python
from agentopt import expose

ROUTER_PROMPT = "Return exactly one intent label."
COACH_PROMPT = "Answer as a practical fitness coach."

def router(text):
    return call_model(ROUTER_PROMPT, text or "")

def coach(text):
    intent = router(text)
    return call_model(COACH_PROMPT, f"intent={intent}\nuser={text or ''}")

run = expose({"default": coach, "router": router})
```

```ts
// Node/TypeScript
import { expose } from "agentopt";

const ROUTER_PROMPT = "Return exactly one intent label.";
const COACH_PROMPT = "Answer as a practical fitness coach.";

const router = (text: string | null) => callModel(ROUTER_PROMPT, text ?? "");
const coach = async (text: string | null) => {
  const intent = await router(text);
  return callModel(COACH_PROMPT, `intent=${intent}\nuser=${text ?? ""}`);
};

export const run = expose({ default: coach, router });
```

```markdown
## Rules
- @router Respond with exactly one known intent label
- Never reveal internal routing labels to the user

## Examples
- @router Input: "switch me to a five-day split" -> exactly "modify_workout"
- @router Input: "what does premium cost?" -> exactly "pricing"
- Input: "switch me to a five-day split" -> mentions five-day

## Qualities
- The final answer is useful without exposing implementation details
```

For tagged cases, agentopt calls only `router`. Untagged cases call `default`
and therefore exercise the production pipeline. Named surfaces require
`run.python` or `run.node`; command and HTTP runners currently ignore the tag.

You can dispatch manually instead of using a map:

```python
def entry(text, surface=None):
    return router(text) if surface == "router" else coach(text)
```

The map form is preferred because agentopt can validate the declared names.

## Trajectory-aware results

Return the answer plus tools, route, and optional usage when checks need to
grade what the agent did. This is especially important in `--code-only` mode,
where there is no wiretap trace.

```python
def run(text):
    answer = answer_with_kb(text)
    return {
        "output": answer,
        "tools": ["search_kb"],
        "route": "tools",
        "usage": {"input": 420, "output": 85},
    }
```

```ts
export async function run(text: string | null) {
  const answer = await answerWithKb(text);
  return {
    output: answer,
    tools: ["search_kb"],
    route: "tools",
    usage: { input: 420, output: 85 },
  };
}
```

```markdown
## Examples
- Input: "Find the cancellation policy" -> calls the search_kb tool
- Input: "Say hello" -> does not call the web_search tool
- Input: "Find the cancellation policy" -> routes as tools
```

## Durable approved cases

`agentopt review` creates this file after a human approves or corrects a traced
answer. You can also add reviewed cases manually. Each `expected` object must
contain exactly one supported check kind.

```yaml
# agentopt.cases.yaml
version: 1
cases:
  - id: incident_refund_over_100
    input: "Refund order 123 for $150"
    expected:
      tool_called: escalate_refund
    group: refunds
    locked: true
    critical: true
    weight: 3
    split: holdout
    provenance:
      source: verified_outcome
      trace_id: run_ab12cd34
      approved_at: "2026-08-15T12:00:00Z"
      approved_by: support-lead
    redaction:
      applied: true
      fields: [order_id]

  - id: approved_pricing_tone
    input: "Is premium worth it?"
    expected:
      quality:
        rubric: "States the correct price and explains the value without pressure"
        good_examples:
          - "Premium is $19.99 monthly and adds personalized plans."
        bad_examples:
          - "Buy it now—you cannot succeed without it."
    group: pricing
    split: auto
    provenance:
      source: manual
      approved_by: product-owner
```

Supported expectation keys are:

- `output_contains`
- `output_equals`
- `classified_as`
- `tool_called`
- `tool_not_called`
- `route`
- `quality` with a `rubric` and optional good/bad examples

Field behavior:

- `group` appears in evaluation coverage reporting.
- `critical` creates a fail-closed veto during candidate verification.
- `weight` changes the case's contribution inside the quality effect size; it
  never trades against constraints, reliability, coverage, or holdout.
- `split: train|holdout` pins the side; `auto` uses the stable hash split.
- `locked` records that automation must not weaken or remove the requirement.
  Current automation only appends approved cases and never edits existing ones.
- `goal_id` is reserved and is not currently used for grouping or weighting.
- Approved cases currently target the default entry; use `GOALS.md` for
  `@surface`-specific checks.

## Managed HTTP agent

```yaml
run:
  http:
    start: "npm run dev"
    ready: "http://127.0.0.1:3000/health"
    url: "http://127.0.0.1:3000/api/chat"
    method: POST
    headers:
      authorization: "Bearer ${AGENTOPT_TEST_TOKEN}"
    body: '{"message":"{input}"}'
    output: "$.reply"
    ready_timeout_ms: 30000
    request_timeout_ms: 120000
```

`{input}` is the evaluation input. `${AGENTOPT_TEST_TOKEN}` is resolved from
the environment and keeps the secret out of version control.

## Attached HTTP agent

Omit `start` and register the wiretap when the development server boots.

```yaml
run:
  http:
    ready: "http://127.0.0.1:3000/health"
    url: "http://127.0.0.1:3000/api/chat"
    body: '{"message":"{input}"}'
    output: "$.reply"
```

```ts
// Next.js instrumentation.ts
export async function register() {
  const { registerServer } = await import("agentopt");
  registerServer();
}
```

```python
# FastAPI/Flask app startup
from agentopt import register_server

register_server()
```

Start the server yourself before `observe`, `eval`, or `improve`. Attach mode
refuses a reachable server that cannot prove the agentopt wiretap is installed.

## A custom judge command

Use your own deterministic or domain-specific scorer instead of the built-in
LLM judge:

```yaml
improver:
  backend: codex
  judge_command: "python scripts/grade.py"
```

The command receives a JSON grading payload on stdin and must write JSON with a
numeric `score` in `[0, 1]` to stdout. Treat stdout as a machine protocol; send
diagnostic logging to stderr.
