# The Workspace — every file agentopt creates

The project-level contract and entry files sit beside your application;
everything else is under `.agentopt/`. Core records are readable Markdown,
YAML, JSON, or JSONL; the optional progress PNG is the only binary report.
The whole system is auditable without a hosted workspace service: these files
stay local.
Your configured agent, judge, optimizer, and code-delegate backends may still
receive prompts/evaluation content as part of their normal model calls.

```
your-project/
├── GOALS.md               you write — what the agent should do
├── agentopt.yaml          you write — how to run it, how the improver behaves
├── agentopt_entry.py       Python entry adapter created by init (or)
├── agentopt.entry.mjs/mts  Node entry adapter created by init
├── agentopt.cases.yaml     you/review write — approved regression cases (optional)
├── playbook.md            agentopt writes — lessons; you load + may veto
└── .agentopt/             agentopt's workspace
    ├── manifest.json
    ├── ledger.json
    ├── observations.json
    ├── pending-attempt.json        only while a code-delegate edit is in flight
    ├── playbook_stats.json
    ├── cache/eval-runs.jsonl       black-box run cache
    ├── traces/<date>/<run_id>.jsonl
    ├── traces/attach.jsonl
    ├── evals/suite.json
    ├── history/v1/{meta.json, files/...}
    ├── logs/improve-<timestamp>.log
    ├── reports/{latest.json, scorecard-*.json, progress.html,
    │            progress.png, versions/vN.md, decisions/*.json,
    │            evidence/<decision-id>/*.json}
    └── review/{pending.md, rejected.jsonl, help_needed.md, simulation.md}
```

Add `.agentopt/` to `.gitignore` if you don't want traces in version control
(committing `history/` and `reports/versions/` can be genuinely useful, though).

## The generated entry adapter

`agentopt init` creates one conventional adapter and points `agentopt.yaml` at
its exported `run` function:

- Python: `agentopt_entry.py`, configured as `agentopt_entry:run`.
- Node JavaScript: `agentopt.entry.mjs`, configured as
  `agentopt.entry.mjs:run`.
- Node TypeScript: `agentopt.entry.mts` when the project has `tsconfig.json`,
  configured as `agentopt.entry.mts:run`.

Edit this small file to import your real agent, supply safe test fixtures, and
return its final answer. It may also use `expose()` to publish several named
handlers for `@surface` checks. These filenames are conveniences generated by
`init`; `run.python` and `run.node` can point to any compatible module and
function. See [Running Your Agent](running-your-agent.md#the-generated-entry-adapter).

## `agentopt.cases.yaml` (project root, optional)

Human-approved regression cases live outside the disposable workspace so they
can be reviewed and committed with the project. `review` appends approved and
corrected trace cases with provenance and redaction metadata; it never promotes
an unreviewed production answer.

The file can also express `group`, `critical`, `weight`, and stable
`train`/`holdout` pins. A missing file is equivalent to an empty case list, so
existing GOALS-only projects behave unchanged. See
[Durable approved cases](examples.md#durable-approved-cases).

## `playbook.md` (project root)

The experience library — one lesson per verified fix, distilled by the
improver ("When outputs consistently omit a required fact, add an explicit
instruction…"). Load it into your agent's prompt with one line:

```python
from agentopt.playbook import load_playbook
system_prompt = BASE_PROMPT + "\n\n" + load_playbook()
```

- delta-updated only (single bullets added/removed — never regenerated, so
  detail never erodes)
- each bullet carries helped/hurt counters (`agentopt playbook` shows them)
- **delete any line you disagree with** (or `agentopt playbook --remove ID`)
  — a human veto is permanent; that lesson is never re-added

## `manifest.json`

The map from everything tunable to its exact source location — built by
`observe` from real traces confirmed by static analysis:

```json
{ "id": "reply_system_prompt", "kind": "prompt",
  "file": "services/replier.py", "line": 4, "source_kind": "literal",
  "slots": [], "content_hash": "…", "editable": true }
```

- `slots` — `{variables}` in f-string prompts that any rewrite must preserve
- `editable: false` + a note = agentopt refuses to guess (dynamic assembly,
  ambiguous duplicates); those get recommendations instead of edits
- `content_hash` powers `drift` — hand-edits since the last observe are detected

## `ledger.json`

The improver's memory: **every attempt ever made**, applied or discarded, with
outcome, reason, and score delta. Failed ideas are fed back into future
proposals ("PREVIOUSLY TRIED AND FAILED — do not repeat") so nothing is
retried across runs. This is the reward memory that makes the loop converge.

## `observations.json`

Recent measured scores for each case (a rolling window of five). The improve
loop uses this cross-run memory to keep intermittent failures visible even when
they happen to pass one snapshot, and to decide when an auto-split holdout case
should rotate into training evidence.

## `cache/eval-runs.jsonl`

The code-only black-box run cache, keyed by working-tree fingerprint, surface,
input, and repeat. It lets an interrupted or unchanged evaluation reuse agent
executions. It stores output/trajectory essentials rather than wiretap events;
observed mode does not use this cache.

## `traces/<date>/<run_id>.jsonl`

One line per event of one agent run: the run metadata, then every LLM call
(model, params, messages, prompt fingerprint, response, tokens, latency,
call site, finish_reason) and tool call. Everything downstream — manifest,
attribution, token budget, `trace` replay — reads from here.

## `evals/suite.json`

The compiled suite, for transparency: what check each goal became, and which
**split** each case landed in:

```json
{ "id": "example_mentions_marco", "layer": 2, "check": "output_contains",
  "origin": "goals", "split": "holdout" }
```

- `split: holdout` answers "why was this never optimized?" — the improver
  can't see holdout cases (overfitting protection); rotation reaches them
  when train is clean
- `origin: adversary` marks provisional evolve-mode challenges (never written
  into your GOALS.md)
- `split_salt` records the current rotation

## `history/vN/`

One folder per applied change — the undo data:

- `meta.json` — description, target entry, files touched, score before/after,
  post-edit hashes
- `files/<path>` — each touched file **as it was before** the change
  (the live improved file is in your working tree)

Consumed by `rollback` (with hand-edit protection), `show`, and `history`.

## `reports/`

| File | What | Updated |
|---|---|---|
| `versions/vN.md` | per-version story: what/why/evidence + before→after diff | at apply time |
| `decisions/<id>.json` | authoritative accepted/rejected gate trace with the deciding stage | for every persisted candidate decision |
| `evidence/<id>/*.json` | baseline, candidate, and holdout scorecards referenced by the decision | with its decision |
| `progress.html` / `.png` | the score-progression chart | after every improve that applied changes, and on `history --html` |
| `latest.json` | last full scorecard — the `check` baseline | on `eval` |
| `scorecard-<ts>.json` | timestamped scorecards | on `eval` |

The ledger and version report store `decision_ref`, so the acceptance story and
the exact evidence used by the gate remain connected.

## `logs/`

Each improve run mirrors timestamped progress to
`logs/improve-<timestamp>.log`. It includes long-running delegate heartbeats and
scoring progress, which is useful when a terminal disconnects or a run fails.

## `pending-attempt.json`

A crash-safety journal written before a physical code-delegate edit. If a prior
process dies before verification, the next improve run uses it to restore the
pre-attempt files before doing new work. It is removed after a normal decision.

## `review/` — the human-in-the-loop inbox

| File | Written by | Meaning |
|---|---|---|
| `help_needed.md` | improve, when stuck | what keeps failing, everything already tried, how to unblock. **Auto-deleted once nothing is stuck** — if it exists, it's live. |
| `simulation.md` | simulate | inconsistent conversations + rule violations, with ready-to-paste GOALS.md lines |
| `pending.md` | `review --export` | a human-readable judgment queue; no automatic checklist importer exists yet |
| `rejected.jsonl` | review | answers rejected without a correction; retained for inspection, but not currently ingested by the improver |

`agentopt status` surfaces whichever of these need you.

Interactive approvals and corrections are promoted to the project-level
`agentopt.cases.yaml`, not written into `GOALS.md`.
